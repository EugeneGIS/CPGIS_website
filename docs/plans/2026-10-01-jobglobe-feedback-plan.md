# JobGlobe 建议实施计划

日期：2026-10-01。状态：本地实现与自动化测试已完成；生产数据库迁移、部署和浏览器验收仍待执行。

依据：用户提供的《2026-09-02 JobGlobe网站建议.docx》及当前项目代码。原文的 12 条建议作为需求输入。原计划阶段仅核对资料；后续已按用户要求进入本地实现阶段。

## 1. 已核对的现状

- 首页仍有独立深色标题区，重复提供导航中的三个入口。
- Partner spotlight 和详情页 Apply now 已声明 `text-white`，但 `globals.css` 中未分层的 `a { color: inherit; }` 优先于 Tailwind 分层样式。需修复颜色规则，而不只是再次增加白字类名；实施时用浏览器计算样式确认。
- 分享使用两种域名来源：地图/列表取 `window.location.origin`，详情和 metadata 使用配置。配置及 URL 校验均可能回退到 `http://localhost:3000`。
- 地图现为 Leaflet + MapLibre/OpenFreeMap 矢量底图，已有英文标签及单独的十段线图层。浅色/暗色线条分别使用红色/粉红色。
- 已找到先前提供的 GS(2020)4619 Shapefile ZIP 和九段线 RAR。现有工程记录确认后者实际有十段线；本轮建议是调整样式和补充整体地图显示，不擅自改变既有几何段数。
- Plan ahead 已按申请截止月份统计，默认隐藏过去月份。当前各组内部升序，需要改为统一倒序，不能退回按发布日期统计。
- 本地数据已有 5,147 条，来源日期范围为 2017-02-09 至 2026-08-28。现有数据的 `department` 全部未独立填写，单位和研究方向主要混在 organization/title/summary 中。
- 已有文档/文本提取、审核状态、社交文案生成和发布标记，但仓库没有定时获取 CSV、X 或 Facebook 数据的任务。社交文案生成不等于外部数据同步。
- 已有 Supabase 接口和 schema；未核验生产环境是否已配置数据库及当前域名。线上旧地址未能通过本次网页读取工具访问，因此以上是本地代码核对结果，不能当作线上实测结论。

## 3. 四批实施与依赖

### 第一批：界面、信息卡和单条分享

范围：第 1、4、5、6、7、8、10、11 项。

- 先修公开域名和链接颜色根因，再做精简布局和统一卡片格式。
- 展示清理复用同一函数，覆盖地图 tooltip、popup、Selected jobs 和详情；不为清理文案重算岗位 ID/slug，以保持已有链接稳定。
- 现有数据没有完整独立的研究方向和单位层级。高置信度内容从已有字段提取；无法确定时保留原文，不猜测机构层级或生成不存在的研究方向。后续导入再补规范字段。
- 所有截止状态使用同一个日期与 7 天阈值；无明确截止日期使用 Open until filled，过期使用 Expired。
- 交付可预览版本和桌面/竖屏/手机对比，验证关键分享链接后发布这一批。

### 第二批：地图显示

范围：第 2、3 项，可在第一批完成后独立交付。

- 复用既有地图转换脚本和来源记录，检查源投影、几何有效性、海岸/行政边界范围及 WGS84 输出，不手绘替代。
- 仅覆盖必要的概览几何；底图标签与边界过滤必须一起处理。单纯叠加透明多边形不会消除底图原有标签。
- 城市/校园尺度隐藏概览覆盖层时，底图的标签规则仍保持一致。
- 公共地图、岗位详情地图和后续分享缩略图采用相同地理显示规则。
- 验证大陆、台湾、港澳、南海、跨世界平移、浅暗主题及校园放大；保留来源署名。

### 第三批：范围分享与 LinkedIn 入口

范围：第 9 项，依赖第一批的域名统一和第二批的地图显示规则。

- 在地图工具栏加入 Share this map。点击后预览范围、筛选条件、岗位数量、日期和缩略图，再复制链接或下载图片。
- 范围查询使用岗位真实坐标，不能依赖重叠点展开后的显示坐标；覆盖跨日期变更线和重复世界场景。与当前列表分页无关，不能只分享最先加载的 5 条。
- 推荐以分享时的岗位 ID 集合、范围、关键词、过期显示开关、生成时间及图片形成可持久保存的分享记录，避免同一链接的预览数量无解释地改变。
- 分享页面标明生成时间，岗位当前状态继续更新；后来撤下或变为非公开的记录不能继续暴露正文。过期岗位保留历史状态说明。
- 先核验生产 Supabase 和图片存储；若尚未配置，在本批接上保存分享记录及图片所需的最小持久化能力。数据同步在第四批复用。
- 生成约 1200 x 630 的地图图片，包含范围内点位、岗位数量、品牌、日期和地图署名；图片与页面公开可取，不依赖访问者浏览器执行地图 JavaScript。
- 用缓存复用生成图片。以实际地图截图/静态渲染原型验证跨域资源、暗色效果和中文标签，不能用任意示意图代替用户所选范围。
- 分享页输出 og:title、og:description、og:url、og:image。LinkedIn 最终预览通过 Post Inspector 验证，并提供图片下载和链接复制作为可用出口。

### 第四批：每日数据更新

范围：第 12 项，依赖数据库和真实输入来源。

- 当前按“优先每日 CSV”编制计划；用户尚未确认文件位置、下载地址和字段。拿到一份样本后确定字段映射与更新含义。
- 建议必需字段为来源标识、来源岗位 ID（如有）、岗位名称、机构、申请链接、发布日期；可选字段包含研究方向、二级单位、截止日期、位置和源更新时间。
- 流程：获取输入 -> 字段/日期/URL 校验 -> 来源身份匹配 -> 去重及变更预览 -> 批量审核 -> 入库发布。
- 导入身份优先使用稳定来源 ID 或来源申请链接，不能仅依赖会因标题编辑变化的显示 slug；同一来源的重复执行应无新增，岗位修改不破坏旧链接。
- 保留来源、输入摘要及导入批次记录；区分新增、更新、无变化、待人工定位和失败。不能覆盖已审核的人工坐标/单位修订，除非显式处理冲突。
- 某条岗位未出现在某天 CSV 中，不默认删除。明确撤回标记和截止日期分别处理。
- 默认自动获取并进入审核队列，管理员批量发布；可信数据源通过验证后再讨论自动发布规则。
- 增加上次成功同步时间、失败记录和重试；发布到公开页面后刷新相应缓存，异常批次保留上一次有效数据。
- 核实云端可访问输入后，在项目内设置日同步任务并支持手动补跑。若 CSV 仅位于个人电脑，需要额外的可靠上传流程，云端不能直接读取该路径。
- 如优先 X/Facebook，先核实具体账号、访问方式和当前 API 权限，再做来源适配；不把现有社交文案生成/“已发布”标记当作读取外部帖子的能力。

## 4. 验证和交付

- 第一批重点：浏览器计算样式、单条公开分享、长标题和单位名称样例、月份倒序与空状态。
- 第二批重点：地图来源与投影、缩放阈值两侧、主题切换、所有地图入口一致。
- 第三批重点：过滤结果和缩略图数量一致、跨日期变更线、空范围、未登录访问、私有/撤下岗位、LinkedIn 抓取。
- 第四批重点：重复导入、来源岗位修改、坏行/坏批次、地理编码失败、审核权限、重试及公开页面更新时间。
- 沿用项目现有单元测试、Python 导入测试、Playwright、lint 和生产 build；按受影响功能补有价值的测试，每批验证后独立发布。
- 本轮仅核对资料并生成计划，不将测试通过或上线状态记作已经完成。
